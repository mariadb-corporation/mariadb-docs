# Install a MariaDB Enterprise License

Several MariaDB products check for a valid license before they start. This page is the starting
point for all of them: it explains the two licensing mechanisms in use, and links to the
product-specific instructions.

{% hint style="info" %}
**Downloading and licensing are separate steps.** Get the software from
[Download MariaDB](https://mariadb.com/downloads/) — enterprise builds under **MariaDB Enterprise
Platform**, evaluation builds under **Trials** — then license it as described below.
{% endhint %}

## Which products need a license

| Product | What the license is | Where you install it |
| ------- | ------------------- | -------------------- |
| [MariaDB MaxScale](https://app.gitbook.com/o/diTpXxF5WsbHqTReoBsS/s/0pSbu5DcMSW4KwAkUcmX/maxscale-management/deployment/installation-and-configuration/maxscale-license-key) | License key | `license_key` in `maxscale.cnf` |
| [MariaDB AI RAG](https://app.gitbook.com/o/diTpXxF5WsbHqTReoBsS/s/kuTXWg0NDbRx6XUeYpGD/enterprise/mariadb-ai-rag/deployment/overview) | License key | `MARIADB_LICENSE_KEY` in `config.env.secure` |
| [GridGain Control Center](https://app.gitbook.com/o/diTpXxF5WsbHqTReoBsS/s/kuTXWg0NDbRx6XUeYpGD/enterprise/control-center/getting-started/adding-license) | GridGain license file | Uploaded in the Control Center UI, or read from disk |

Products not listed here do not require a license to run. MariaDB Enterprise Server, for example,
is authenticated at download time with a Customer Download Token rather than a license at runtime —
see [MariaDB Package Repository Setup](https://app.gitbook.com/o/diTpXxF5WsbHqTReoBsS/s/SsmexDFPv2xG2OTyO5yV/server-management/install-and-upgrade-mariadb/mariadb-package-repository-setup-and-usage).

## License keys

MariaDB MaxScale and MariaDB AI RAG use a **license key**: a signed token that you paste into the
product's configuration. The key is generated by you, on demand, from the MariaDB License Portal.

A MariaDB Enterprise Platform subscription comes with one license key that covers the products in
your subscription. You do not need a separate key for each product.

### Get a license key

1. Navigate to the [MariaDB License Portal](https://customers.mariadb.com/license/).
2. Sign in with your MariaDB ID. If you do not have an account, you can create one using your
   email, Google, GitHub, or LinkedIn credentials.
3. On the **License Products** page, select the **Enterprise** tab, then generate a key from the
   card for your subscription.

   If you are evaluating a product, select the **Trial** tab instead, then click **Get License**
   on the product's trial card and follow the prompts.
4. Copy or download the key.
5. Install the key as described in the product's documentation.

{% hint style="info" %}
Trial license keys are valid for 30 days from the date they are issued. The duration of a
subscription key is set by your subscription.
{% endhint %}

### Install a license key

The key goes in a different place for each product:

{% tabs %}
{% tab title="MaxScale" %}
Add `license_key` to the `[maxscale]` section of `/etc/maxscale.cnf`. The value is either the key
itself or the absolute path to a file containing it.

```ini
[maxscale]
license_key=eyJhbGciOiJSUzI1NiIsInR5cCI6IkpXVCIsImtpZCI6...
```

Full instructions, including renewal and troubleshooting:
[Install a MaxScale License Key](https://app.gitbook.com/o/diTpXxF5WsbHqTReoBsS/s/0pSbu5DcMSW4KwAkUcmX/maxscale-management/deployment/installation-and-configuration/maxscale-license-key).

On Kubernetes, MariaDB Enterprise Operator reads the key from a Secret and passes it to MaxScale.
See [MaxScale licensing](https://app.gitbook.com/o/diTpXxF5WsbHqTReoBsS/s/kuTXWg0NDbRx6XUeYpGD/enterprise/mariadb-enterprise-operator/topologies/maxscale#licensing)
in the Operator documentation.
{% endtab %}

{% tab title="AI RAG" %}
Set `MARIADB_LICENSE_KEY` in `config.env.secure`.

```bash
MARIADB_LICENSE_KEY=eyJhbGciOiJSUzI1NiIsInR5cCI6IkpXVCIsImtpZCI6...
```

Full instructions: [AI RAG deployment](https://app.gitbook.com/o/diTpXxF5WsbHqTReoBsS/s/kuTXWg0NDbRx6XUeYpGD/enterprise/mariadb-ai-rag/deployment/overview).
{% endtab %}
{% endtabs %}

### What happens when a key is missing or expired

Both products validate the key at startup and **will not start** without a valid one. Check the
product's log for the reason. A malformed key and an expired key each produce a distinct
message.

Behavior differs once the product is already running:

* **MaxScale** stops when its license expires while it is running. Before that, it logs
  increasingly frequent messages about the expiry in the MaxScale log.
* **AI RAG** validates only at startup, so a lapsed license takes effect the next time it
  restarts.

## GridGain license files

GridGain products use a GridGain license: an XML file signed by GridGain, issued to you by the
sales team, carrying a license type, an expiry date, and node and CPU quotas. GridGain licenses are
issued separately from a MariaDB Enterprise Platform subscription and do not come from the MariaDB
License Portal.

{% hint style="info" %}
Starting with GridGain 8.10 and 9.2, GridGain also accepts a GridGain license key in the same
format that MaxScale uses. Earlier versions accept only the XML license, and existing XML licenses
keep working after an upgrade, so this page covers the XML license.
{% endhint %}

There are two of them, and they are separate things:

* The **Control Center product license**, which licenses the Control Center installation itself.
* The **cluster license**, installed on the GridGain cluster, which licenses the cluster and
  declares which features it is entitled to.
