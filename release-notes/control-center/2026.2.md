# Control Center 2026.2 Release Notes

## What's New in This Release

GridGain® Control Center is a comprehensive, customizable cluster management and developer tool for GridGain applications. Use Control Center to query data across caches, monitor performance metrics, define and track production alerts, take snapshots for backup and recovery, and collect and analyze API traces. The latest Control Center release, 2026.2, includes new features, as well as improvements and issue resolutions.

## Major Changes

### Supported Cluster Scope

Control Center no longer supports GridGain 8.8 and older. GridGain Community Edition, Apache Ignite 2, and Apache Ignite 3 clusters are no longer monitored, but attached ones remain visible.

## GridGain 9 Connector Support Scope

GridGain Control Center supports GridGain 9 versions 9.1.0 and later.

You need to update [Cloud Connector](https://app.gitbook.com/s/kuTXWg0NDbRx6XUeYpGD/enterprise/control-center/gg9/cloud-connector/connect-cloud-connector) to the latest version (2026.2) to securely connect your GridGain 9 cluster to Control Center.

## New Features

### Data and Schema Import for GridGain 8

The **Data and Schema Import** feature now supports GridGain 8 clusters. Users can import schemas from external relational databases (including MySQL, PostgreSQL, and MariaDB) via JDBC, or from Apache Iceberg tables via REST and JDBC catalogs, into an active GridGain 8 cluster. The import process covers connection setup, schema and table selection, GridGain 8 storage configuration, column type mapping, index settings, optional data import, and a final review of the generated scripts before execution. See [Data and Schema Import](https://app.gitbook.com/s/kuTXWg0NDbRx6XUeYpGD/enterprise/control-center/gg8/data-schema-import) for details.

### Cluster-License-Based Access to Control Center

Control Center is now available on any attached cluster whose GridGain license includes the `CONTROL_CENTER` feature, with no separate purchase or file needed. Existing Control Center licenses keep working. GridGain Community Edition, Apache Ignite 2, and Apache Ignite 3 clusters are no longer monitored. See [Managing License](https://app.gitbook.com/s/kuTXWg0NDbRx6XUeYpGD/enterprise/control-center/admin-guide/license) for details.

### Run control.sh Commands from Control Center

For GridGain 8 clusters, you can run `control.sh` commands for the selected cluster through the Control Center agent, without shell access to a cluster node. This requires GridGain 8.9.34 or later, or GridGain 8.10. See [Cluster Terminal](https://app.gitbook.com/s/kuTXWg0NDbRx6XUeYpGD/enterprise/control-center/gg8/terminal/cluster-terminal) for details.

### Enterprise Manager Integration

MariaDB Enterprise Manager can now show the GridGain 8 clusters that Control Center monitors and open them in Control Center with single sign-on. To enable the integration, configure Enterprise Manager as the `em` OpenID Connect provider in Control Center, then connect Control Center on the Enterprise Manager side.

Control Center maps the Enterprise Manager `admin` role to Control Center administrator access, and all other roles to regular access. See [Enterprise Manager Integration](https://app.gitbook.com/s/kuTXWg0NDbRx6XUeYpGD/enterprise/control-center/admin-guide/enterprise-manager-integration) for details.

### Global Team and Cluster Auto-Attach Enabled by Default

Control Center now ships with `account.globalTeam.enabled` and `account.globalTeam.attachCluster` set to `true`, so every connected cluster is visible to every user without an attach step. To restore the previous behavior, set both properties to `false`. See [Configuration Parameters](https://app.gitbook.com/s/kuTXWg0NDbRx6XUeYpGD/enterprise/control-center/admin-guide/configuration#teams) for details.

### In-App Notification Channel

Alerts can now be delivered to Control Center users as in-app notifications. Create an `IN_APP` notification channel with a list of user names via the REST API, assign it to an alert, and the listed users receive the alert in the **Notifications** panel. See [Configure In-App Notifications](https://app.gitbook.com/s/kuTXWg0NDbRx6XUeYpGD/enterprise/control-center/gg8/alerting#configure-in-app-notifications) for details.

### Software Bill of Materials (SBOM)

Control Center and Cloud Connector downloads and Docker images now come with a CycloneDX 1.6 Software Bill of Materials (SBOM) that lists their components, so you can track third-party components and scan them for known vulnerabilities. See [Software Bill of Materials (SBOM)](https://app.gitbook.com/s/kuTXWg0NDbRx6XUeYpGD/enterprise/control-center/admin-guide/sbom) for details.

### Pre-deployed Unit for CDC to GridGain 8

Control Center now lists the built-in deployment unit that GridGain 9.1.24 and later clusters include for Change Data Capture (CDC) replication to GridGain 8. See [Pre-deployed Unit](https://app.gitbook.com/s/kuTXWg0NDbRx6XUeYpGD/enterprise/control-center/gg9/deployment/code-deployment-gg9#pre-deployed-unit) for details.

## Updating to 2026.2

You can update Control Center to 2026.2 from 2022.2 and more recent versions. To update from older versions, update to [2022.2](2022.2.md) first.

1. If you haven't yet, update to Java 17 or 21.
2. Follow the [update instructions](https://app.gitbook.com/s/kuTXWg0NDbRx6XUeYpGD/enterprise/control-center/admin-guide/installation/update).

{% hint style="info" %}
In Control Center 2025.1, the default [TTL](https://app.gitbook.com/s/kuTXWg0NDbRx6XUeYpGD/enterprise/control-center/admin-guide/configuration#time-to-live-limits) parameters were reduced from 7 days to 1 day. When upgrading from versions earlier than 2025.1, explicitly set the required TTL values in the Control Center configuration **before version upgrade**.
{% endhint %}

### Updating to 2026.2 with an External Cluster

An [external](https://app.gitbook.com/s/kuTXWg0NDbRx6XUeYpGD/enterprise/control-center/admin-guide/external-cluster) GridGain 8 cluster stores Control Center's internal data. It is separate from the clusters connected to Control Center for monitoring and management.

Starting with this release, the external cluster must run GridGain **8.9.38 or newer** to remain compatible with the internal Control Center client node.

This version requirement does not apply to monitored clusters, which can run any supported GridGain 8 version.

Follow these steps to perform the update correctly:

1. Stop Control Center.
2. If an external cluster upgrade is required, follow [upgrade instruction](https://www.gridgain.com/docs/gridgain8/latest/installation-guide/upgrades) or enable [rolling upgrade](https://www.gridgain.com/docs/gridgain8/latest/installation-guide/rolling-upgrades).
3. If you haven't yet, update Control Center to Java 17 or 21.
4. Proceed with the standard Control Center [update instructions](https://app.gitbook.com/s/kuTXWg0NDbRx6XUeYpGD/enterprise/control-center/admin-guide/installation/update).
