# MariaDB ColumnStore 23.02.19 Release Notes

{% hint style="info" %}
ColumnStore 23.02.19 works with MariaDB Enterprise Server 10.6.
{% endhint %}

**Release date:** 5 May 2026

MariaDB ColumnStore 23.02.19 is a [Stable (GA)](../../community-server/about/release-criteria.md) release of MariaDB ColumnStore.

{% hint style="info" %}
ColumnStore 23.02.18 was a custom build and was not published, so these notes list the changes since [23.02.17](23.02.17.md).
{% endhint %}

## Notable changes

* \[[MCOL-6293](https://jira.mariadb.org/browse/MCOL-6293)] - Added the `INFORMATION_SCHEMA.COLUMNSTORE_PARTITIONS` table, which lists the partitions of ColumnStore tables and columns; its `PARTITION_ID` values are compatible with `CALSHOWPARTITIONS()` and `CALDROPPARTITIONS()`

## Issues fixed

### Can result in hang or crash

* \[[MCOL-6204](https://jira.mariadb.org/browse/MCOL-6204)] - Workernode crashed when a signal arrived during startup
* \[[MCOL-6316](https://jira.mariadb.org/browse/MCOL-6316)] - A race between Extent Map index reads and writes could crash a process with `SIGSEGV`
* \[[MCOL-6325](https://jira.mariadb.org/browse/MCOL-6325)] - PrimProc could crash on a null pointer dereference in `TupleBPS::sendError()`

### Can return wrong results

* \[[MCOL-6326](https://jira.mariadb.org/browse/MCOL-6326)] - After an interrupted or failed `cpimport`, `MAX()` and `MIN()` could return invalid values such as `0000-00-00`, because the rollback did not clear the extents' minimum and maximum metadata

### Other fixes

* \[[MCOL-5056](https://jira.mariadb.org/browse/MCOL-5056)] - Cross-engine joins on `TEXT` columns from InnoDB tables failed
* \[[MCOL-6178](https://jira.mariadb.org/browse/MCOL-6178)] - The ColumnStore shell aliases in `/etc/profile` let unprivileged users control the cluster; they now use the `mcs` command and are defined only for privileged users
* \[[MCOL-6297](https://jira.mariadb.org/browse/MCOL-6297)] - Cross-engine queries could fail with error 1815 because of incorrect predicate pushdown
