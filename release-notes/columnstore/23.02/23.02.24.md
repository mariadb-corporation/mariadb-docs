# MariaDB ColumnStore 23.02.24 Release Notes

{% include "../../.gitbook/includes/unreleased-columnstore-23.02.md" %}

{% hint style="info" %}
ColumnStore 23.02.24 works with MariaDB Enterprise Server 10.6.
{% endhint %}

**Release date:** TBD

MariaDB ColumnStore 23.02.24 is a [Stable (GA)](../../community-server/about/release-criteria.md) release of MariaDB ColumnStore.

## Fixed security vulnerabilities

The bundled Apache Thrift library was updated from 0.23.0 to 0.24.0, which resolves the following vulnerabilities in the C++ bindings that ColumnStore uses:

* [CVE-2026-48145](https://www.cve.org/CVERecord?id=CVE-2026-48145)
* [CVE-2026-48586](https://www.cve.org/CVERecord?id=CVE-2026-48586)
* [CVE-2026-55969](https://www.cve.org/CVERecord?id=CVE-2026-55969)
* [CVE-2026-55970](https://www.cve.org/CVERecord?id=CVE-2026-55970)
* [CVE-2026-58662](https://www.cve.org/CVERecord?id=CVE-2026-58662)

## Notable changes

* \[[MCOL-6434](https://jira.mariadb.org/browse/MCOL-6434)] - The Block Resolution Manager now stores its shared memory on a versioned, copy-on-write scheme, so a fatal signal can no longer leave the extent map in a partially written state
* \[[MCOL-6513](https://jira.mariadb.org/browse/MCOL-6513)] - Updated the bundled Apache Thrift to 0.24.0

## Issues fixed

### Can result in hang or crash

* \[[MCOL-6512](https://jira.mariadb.org/browse/MCOL-6512)] - Fixed a potential SIGSEGV in MCSSETPARMS/CALSETPARMS processing
* \[[MCOL-6528](https://jira.mariadb.org/browse/MCOL-6528)] - PrimProc could reach an inconsistent aggregation state, leading to excessive memory use and a crash

### Can result in data corruption

* \[[MCOL-6434](https://jira.mariadb.org/browse/MCOL-6434)] - Corruption of BRM data after a fatal unrecoverable signal
