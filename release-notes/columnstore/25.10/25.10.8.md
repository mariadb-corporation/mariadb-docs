# MariaDB ColumnStore 25.10.8 Release Notes

{% hint style="info" %}
ColumnStore 25.10.8 works with MariaDB Enterprise Server 10.6, 11.4, and 11.8.
{% endhint %}

**Release date:** 29 Oct 2026

MariaDB ColumnStore 25.10.8 is a [Stable (GA)](../../community-server/about/release-criteria.md) release of MariaDB ColumnStore.

## Fixed security vulnerabilities

* \[MCOL-6666] - Fixed a vulnerability in the Cluster Management API (CMAPI) that let a remote user who could reach the CMAPI port run commands as `root` without authenticating

The bundled Apache Thrift library was updated from 0.24.0 to 0.25.0, which resolves the following vulnerabilities. ColumnStore bundles only the Thrift C++ bindings, so vulnerabilities that affect only other language bindings are not listed.

* [CVE-2026-66055](https://www.cve.org/CVERecord?id=CVE-2026-66055)
* [CVE-2026-82458](https://www.cve.org/CVERecord?id=CVE-2026-82458)
* [CVE-2026-83632](https://www.cve.org/CVERecord?id=CVE-2026-83632)
* [CVE-2026-91135](https://www.cve.org/CVERecord?id=CVE-2026-91135)
* [CVE-2026-93925](https://www.cve.org/CVERecord?id=CVE-2026-93925)
* [CVE-2026-93926](https://www.cve.org/CVERecord?id=CVE-2026-93926)

## Notable changes

* \[[MCOL-6496](https://jira.mariadb.org/browse/MCOL-6496)] - The Block Resolution Manager now stores its shared memory on a versioned, copy-on-write scheme, so a fatal signal can no longer leave the extent map in a partially written state
* \[[MCOL-6673](https://jira.mariadb.org/browse/MCOL-6673)] - Updated the bundled Apache Thrift to 0.25.0

## Issues fixed

### Can result in data corruption

* \[[MCOL-6496](https://jira.mariadb.org/browse/MCOL-6496)] - Corruption of BRM data after a fatal unrecoverable signal

### Related to install and upgrade

* \[[MCOL-6518](https://jira.mariadb.org/browse/MCOL-6518)] - The upgrade prechecks now check the MariaDB replication status
* \[[MCOL-6410](https://jira.mariadb.org/browse/MCOL-6410)] - The upgrade prechecks now check the Cross Engine Join (CEJ) credentials
* \[[MCOL-6191](https://jira.mariadb.org/browse/MCOL-6191)] - Upgrades now report which node they are working on, log more detail, and give a clearer error when the target version doesn't support the upgrade APIs
* \[[MCOL-6667](https://jira.mariadb.org/browse/MCOL-6667)] - SELinux could block `cpimport` from checking whether another process was running, which could make `cpimport` fail, mostly on Oracle Linux

### Other fixes

* \[[MCOL-6338](https://jira.mariadb.org/browse/MCOL-6338)] - `mcsRebuildEM` could fail to rebuild the extent map for larger data sets, so later queries failed
