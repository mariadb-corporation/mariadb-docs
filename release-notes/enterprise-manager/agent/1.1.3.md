# MariaDB Enterprise Manager Agent 1.1.3 Release Notes

**Release Date:** 22 Oct 2026

Release 1.1.3 of `mema-agent`, the MariaDB Enterprise Manager agent, is a GA release. It is available from the MariaDB Enterprise Tools repository.

### Notable Changes <a href="#notable-changes" id="notable-changes"></a>

#### Installing the package no longer starts the agent

The packages enable no services when they are installed. After installing, run `mema-agent setup`, which writes the collector configuration and the exporter credentials file and enables `mema-agent.target`. For the full procedure, see [Agent Installation]({tools}/enterprise/mariadb-enterprise-manager/administration/deployment/adding-databases/agent-installation-t-copy).

This changes the behavior of the deb packages, which could enable and start the services at install time. The services read files that only `mema-agent setup` writes, and without the credentials file the MariaDB exporter exits during configuration validation, so starting the services on install left a failed unit on every new installation. The rpm packages already behaved this way.

#### Upgrading restarts a running agent

After an upgrade, the package runs `systemctl daemon-reload` and `systemctl try-restart mema-agent.target`, so a running agent switches to the new binaries immediately. An agent that is not running is not started.

Releases up to and including 1.1.0 don't do this. After installing one of them, run:

```bash
sudo systemctl daemon-reload
sudo systemctl restart mema-agent.target
```

#### Nodes set up with OTLP basic authentication need `mema-agent setup` run again

On a node set up with `--otlp-user` and `--otlp-password`, the collector never started on any 1.0.x agent. The generated configuration declared the `basicauth/client` extension but didn't enable it under `service`, so the collector exited at startup with `failed to resolve authenticator "basicauth/client"` and the node sent no metrics, even though `mema-agent setup` reported success.

Upgrading the package doesn't rewrite that configuration. After upgrading such a node, run `mema-agent setup` again with the same flags. Nodes set up without OTLP credentials aren't affected.

### Platforms <a href="#platforms" id="platforms"></a>

Packages are available for x86\_64 and ARM64 (aarch64). The binaries are statically linked, so one package per format and architecture covers every supported distribution:

* RPM: RHEL 8, 9, and 10, including compatible distributions such as Rocky Linux and AlmaLinux, and SLES 15
* DEB: Ubuntu 22.04, 24.04, and 26.04, and Debian 12 and 13

### Packaging <a href="#packaging" id="packaging"></a>

* The agent is delivered as the `mema-agent` OS package (RPM and DEB) in the MariaDB Enterprise Tools repository
* Each package has a CycloneDX SBOM, generated from the unpacked package, so it describes the OpenTelemetry Collector, the node exporter, and the MariaDB exporter rather than only the package wrapper
