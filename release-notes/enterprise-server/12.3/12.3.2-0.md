MariaDB Enterprise Server 12.3.2-0 is a Beta release of [MariaDB Enterprise Server 12.3](whats-new.md), the first release in the 12.3 series. It is based on MariaDB Community Server 12.3.2 and adds the Enterprise-only capabilities described below.

## Notable changes

Because this is the first release in the series, the changes are the full set of features added since [MariaDB Enterprise Server 11.8](../11.8/whats-new.md). The highlights:

* **MariaDB Advanced Cluster 0.9.1** — a replication provider built on the Raft consensus protocol, delivered as the `raft` plugin, with its own system variables, status variables, and `RAFT_*` Information Schema tables
* **Conflict Detection and Resolution triggers** — `FOR CONFLICT` triggers that resolve row-based replication conflicts on the replica, with the new `ORG` row accessor for the primary's before-image ([MENT-2033](https://jira.mariadb.org/browse/MENT-2033))
* **Password-less authentication with TLS certificates** — the new `tls_certificate` authentication plugin, which authenticates a client from its TLS certificate against the account's `REQUIRE SUBJECT` clause ([MENT-2425](https://jira.mariadb.org/browse/MENT-2425))
* **Optimizer hints** — inline hints for join order, index selection, subquery strategy, and execution time
* **Binary log in InnoDB** — the binary log can be stored in InnoDB, removing the need to sync it ([MDEV-34705](https://jira.mariadb.org/browse/MDEV-34705))
* **Oracle compatibility** — `TO_DATE()`, `TO_NUMBER()`, `TRUNC()`, `( + )` outer join syntax, cursors on prepared statements, and `SYS_REFCURSOR`
* **New GIS functions** — nine functions improving MySQL 8 compatibility
* **MariaDB Enterprise Audit** — connection records now log the client port alongside the host, and `CONNECT` events record the TLS version ([MENT-2470](https://jira.mariadb.org/browse/MENT-2470), [MENT-2471](https://jira.mariadb.org/browse/MENT-2471))

For the complete list, see [What's New in MariaDB Enterprise Server 12.3](whats-new.md).

## Incompatible Changes

{% hint style="warning" %}
This release is based on MariaDB 12.3.2. When a replica is upgraded to it, the `CHANGE MASTER TO ... master_use_gtid` setting is not carried over and is reset to `DEFAULT`. After upgrading, re-apply `master_use_gtid` if you rely on it. Downgrading is not affected. The underlying fix landed in MariaDB 12.3.3 ([MDEV-39788](https://jira.mariadb.org/browse/MDEV-39788)).
{% endhint %}

The following keywords are now [reserved words](https://app.gitbook.com/o/diTpXxF5WsbHqTReoBsS/s/SsmexDFPv2xG2OTyO5yV/reference/sql-structure/sql-language-structure/reserved-words) and must be quoted if used as identifiers: `CONVERSION`, `ST_COLLECT`, `TO_DATE`.

The deprecated `big_tables`, `large_page_size`, and `storage_engine` system variables have been removed.

See [Incompatible Changes](whats-new.md#incompatible-changes) for details.
