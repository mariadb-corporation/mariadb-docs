MariaDB Enterprise Server 12.3.3-0 is a Beta release of [MariaDB Enterprise Server 12.3](whats-new.md), the first release in the 12.3 series. It is based on MariaDB Community Server 12.3.3 and adds the Enterprise-only capabilities described below.

## Notable changes

Because this is the first release in the series, the changes are the full set of features added since [MariaDB Enterprise Server 11.8](../11.8/whats-new.md). The highlights:

* [**MariaDB Advanced Cluster**](../../advanced-cluster/README.md) **0.9.1** — a replication provider built on the Raft consensus protocol, delivered as the `raft` plugin, with its own system variables, status variables, and `RAFT_*` Information Schema tables
* **Conflict Detection and Resolution triggers** — `FOR CONFLICT` triggers that resolve row-based replication conflicts on the replica, with the new `ORG` row accessor for the primary's before-image ([MENT-2033](https://jira.mariadb.org/browse/MENT-2033))
* **Password-less authentication with TLS certificates** — the new `tls_certificate` authentication plugin, which authenticates a client from its TLS certificate against the account's `REQUIRE SUBJECT` clause ([MENT-2425](https://jira.mariadb.org/browse/MENT-2425))
* [**Optimizer hints**](https://app.gitbook.com/o/diTpXxF5WsbHqTReoBsS/s/SsmexDFPv2xG2OTyO5yV/ha-and-performance/optimization-and-tuning/optimizer-hints) — inline hints for join order, index selection, subquery strategy, and execution time
* **Storage-engine-integrated binary log** — a more efficient binary log implementation that uses InnoDB internals to write the binary log, removing the need to sync it. Enabled with the read-only [binlog\_storage\_engine](https://app.gitbook.com/o/diTpXxF5WsbHqTReoBsS/s/SsmexDFPv2xG2OTyO5yV/ha-and-performance/standard-replication/replication-and-binary-log-system-variables#binlog_storage_engine) option ([MDEV-34705](https://jira.mariadb.org/browse/MDEV-34705))
* **Oracle compatibility** — [TO\_DATE()](https://app.gitbook.com/o/diTpXxF5WsbHqTReoBsS/s/SsmexDFPv2xG2OTyO5yV/reference/sql-functions/date-time-functions/to_date), [TO\_NUMBER()](https://app.gitbook.com/o/diTpXxF5WsbHqTReoBsS/s/SsmexDFPv2xG2OTyO5yV/reference/sql-functions/numeric-functions/to_number), [TRUNC()](https://app.gitbook.com/o/diTpXxF5WsbHqTReoBsS/s/SsmexDFPv2xG2OTyO5yV/reference/sql-functions/date-time-functions/trunc), [`( + )` outer join syntax](https://app.gitbook.com/o/diTpXxF5WsbHqTReoBsS/s/SsmexDFPv2xG2OTyO5yV/reference/sql-statements/data-manipulation/selecting-data/joins/join-syntax#oracle-mode), [cursors](https://app.gitbook.com/o/diTpXxF5WsbHqTReoBsS/s/SsmexDFPv2xG2OTyO5yV/reference/sql-statements/programmatic-compound-statements/programmatic-compound-statements-cursors) on prepared statements, and `SYS_REFCURSOR`
* **New GIS functions** — [ST\_Validate](https://app.gitbook.com/o/diTpXxF5WsbHqTReoBsS/s/SsmexDFPv2xG2OTyO5yV/reference/sql-statements/geometry-constructors/miscellaneous-gis-functions/st_validate), [ST\_IsValid](https://app.gitbook.com/o/diTpXxF5WsbHqTReoBsS/s/SsmexDFPv2xG2OTyO5yV/reference/sql-statements/geometry-constructors/miscellaneous-gis-functions/st_isvalid), [ST\_Simplify](https://app.gitbook.com/o/diTpXxF5WsbHqTReoBsS/s/SsmexDFPv2xG2OTyO5yV/reference/sql-statements/geometry-constructors/miscellaneous-gis-functions/st_simplify), [ST\_Collect](https://app.gitbook.com/o/diTpXxF5WsbHqTReoBsS/s/SsmexDFPv2xG2OTyO5yV/reference/sql-statements/geometry-constructors/miscellaneous-gis-functions/st_collect), [MBRCoveredBy](https://app.gitbook.com/o/diTpXxF5WsbHqTReoBsS/s/SsmexDFPv2xG2OTyO5yV/reference/sql-statements/geometry-constructors/mbr-minimum-bounding-rectangle/mbrcoveredby), [ST\_GeoHash](https://app.gitbook.com/o/diTpXxF5WsbHqTReoBsS/s/SsmexDFPv2xG2OTyO5yV/reference/sql-statements/geometry-constructors/miscellaneous-gis-functions/st_geohash), [ST\_LatFromGeoHash](https://app.gitbook.com/o/diTpXxF5WsbHqTReoBsS/s/SsmexDFPv2xG2OTyO5yV/reference/sql-statements/geometry-constructors/miscellaneous-gis-functions/st_latfromgeohash), [ST\_LongFromGeoHash](https://app.gitbook.com/o/diTpXxF5WsbHqTReoBsS/s/SsmexDFPv2xG2OTyO5yV/reference/sql-statements/geometry-constructors/miscellaneous-gis-functions/st_longfromgeohash), and [ST\_PointFromGeoHash](https://app.gitbook.com/o/diTpXxF5WsbHqTReoBsS/s/SsmexDFPv2xG2OTyO5yV/reference/sql-statements/geometry-constructors/miscellaneous-gis-functions/st_pointfromgeohash), improving MySQL 8 compatibility
* [**MariaDB Enterprise Audit**](https://app.gitbook.com/o/diTpXxF5WsbHqTReoBsS/s/SsmexDFPv2xG2OTyO5yV/reference/plugins/mariadb-enterprise-audit) — connection records now log the client port alongside the host, and `CONNECT` events record the TLS version ([MENT-2470](https://jira.mariadb.org/browse/MENT-2470), [MENT-2471](https://jira.mariadb.org/browse/MENT-2471))

For the complete list, see [What's New in MariaDB Enterprise Server 12.3](whats-new.md).

## Changes in Storage Engines

<!-- TODO: revisit once the ColumnStore issues are fixed — ColumnStore is expected to return in a later 12.3 release, at which point this section needs its engine version back. -->

* MariaDB ColumnStore is not included in this Beta release. It is expected to return in a later release in the 12.3 series.
* The Videx storage engine, added in MariaDB Community Server 12.3, is not shipped with MariaDB Enterprise Server ([MENT-2629](https://jira.mariadb.org/browse/MENT-2629)).

## Incompatible Changes

The following keywords are now [reserved words](https://app.gitbook.com/o/diTpXxF5WsbHqTReoBsS/s/SsmexDFPv2xG2OTyO5yV/reference/sql-structure/sql-language-structure/reserved-words) and must be quoted if used as identifiers: `CONVERSION`, `ST_COLLECT`, `TO_DATE`.

The deprecated `big_tables`, `large_page_size`, and `storage_engine` system variables have been removed.

See [Incompatible Changes](whats-new.md#incompatible-changes) for details.
