# Release Notes for MariaDB Enterprise Server 12.3.3-1

<a href="https://mariadb.com/downloads/enterprise/enterprise-server/" class="button primary">Download</a> <a class="button secondary">Release Notes</a> <a href="whats-new.md" class="button secondary">Overview of Enterprise Server 12.3</a>

**Release date:** 3 Nov 2026

MariaDB Enterprise Server 12.3.3-1 is the first Stable (GA) release of [MariaDB Enterprise Server 12.3](whats-new.md). It is based on MariaDB Community Server 12.3.3 and adds the Enterprise-only capabilities described below.

## Notable Changes

Because this is the first Stable (GA) release in the series, the changes are the full set of features added since [MariaDB Enterprise Server 11.8](../11.8/whats-new.md). The highlights:

* [**MariaDB Raft Cluster**]({raft-cluster}) **1.0.0** — a replication provider built on the Raft consensus protocol, delivered as the `raft` plugin, with its own system variables, status variables, and `RAFT_*` Information Schema tables. The Raft log can be encrypted at rest with the same `encrypt_binlog` setting and key management plugins as the binary log
* **Conflict Detection and Resolution** — `FOR CONFLICT` triggers that resolve row-based replication conflicts on the replica, with the new `ORG` row accessor for the primary's before-image ([MENT-2033](https://jira.mariadb.org/browse/MENT-2033))
* **Password-less authentication with TLS certificates** — the new `tls_certificate` authentication plugin, which authenticates a client from its TLS certificate against the account's `REQUIRE SUBJECT` clause ([MENT-2425](https://jira.mariadb.org/browse/MENT-2425))
* **Passphrase-protected TLS keys** — a private key protected by a passphrase can now be used, with the passphrase supplied through the [ssl\_passphrase](https://app.gitbook.com/s/SsmexDFPv2xG2OTyO5yV/security/encryption/data-in-transit-encryption/ssltls-system-variables#ssl_passphrase) system variable
* [**Optimizer hints**](https://app.gitbook.com/s/SsmexDFPv2xG2OTyO5yV/ha-and-performance/optimization-and-tuning/optimizer-hints) — inline hints for join order, index selection, subquery strategy, and execution time
* **InnoDB-based binary log** — binary log events can now be written to InnoDB-managed, page-structured files (`.ibb`) that are integrated with InnoDB's redo log and crash recovery, removing the costly two-phase commit between the binary log and InnoDB. Enabled with the read-only [binlog\_storage\_engine](https://app.gitbook.com/s/SsmexDFPv2xG2OTyO5yV/ha-and-performance/standard-replication/replication-and-binary-log-system-variables#binlog_storage_engine) option ([MDEV-34705](https://jira.mariadb.org/browse/MDEV-34705))
* **Oracle compatibility** — [TO\_DATE()](https://app.gitbook.com/s/SsmexDFPv2xG2OTyO5yV/reference/sql-functions/date-time-functions/to_date), [TO\_NUMBER()](https://app.gitbook.com/s/SsmexDFPv2xG2OTyO5yV/reference/sql-functions/numeric-functions/to_number), [TRUNC()](https://app.gitbook.com/s/SsmexDFPv2xG2OTyO5yV/reference/sql-functions/date-time-functions/trunc), [`( + )` outer join syntax](https://app.gitbook.com/s/SsmexDFPv2xG2OTyO5yV/reference/sql-statements/data-manipulation/selecting-data/joins/join-syntax#oracle-mode), [cursors](https://app.gitbook.com/s/SsmexDFPv2xG2OTyO5yV/reference/sql-statements/programmatic-compound-statements/programmatic-compound-statements-cursors) on prepared statements, and `SYS_REFCURSOR`
* **New GIS functions** — [ST\_Validate](https://app.gitbook.com/s/SsmexDFPv2xG2OTyO5yV/reference/sql-statements/geometry-constructors/miscellaneous-gis-functions/st_validate), [ST\_IsValid](https://app.gitbook.com/s/SsmexDFPv2xG2OTyO5yV/reference/sql-statements/geometry-constructors/miscellaneous-gis-functions/st_isvalid), [ST\_Simplify](https://app.gitbook.com/s/SsmexDFPv2xG2OTyO5yV/reference/sql-statements/geometry-constructors/miscellaneous-gis-functions/st_simplify), [ST\_Collect](https://app.gitbook.com/s/SsmexDFPv2xG2OTyO5yV/reference/sql-statements/geometry-constructors/miscellaneous-gis-functions/st_collect), [MBRCoveredBy](https://app.gitbook.com/s/SsmexDFPv2xG2OTyO5yV/reference/sql-statements/geometry-constructors/mbr-minimum-bounding-rectangle/mbrcoveredby), [ST\_GeoHash](https://app.gitbook.com/s/SsmexDFPv2xG2OTyO5yV/reference/sql-statements/geometry-constructors/miscellaneous-gis-functions/st_geohash), [ST\_LatFromGeoHash](https://app.gitbook.com/s/SsmexDFPv2xG2OTyO5yV/reference/sql-statements/geometry-constructors/miscellaneous-gis-functions/st_latfromgeohash), [ST\_LongFromGeoHash](https://app.gitbook.com/s/SsmexDFPv2xG2OTyO5yV/reference/sql-statements/geometry-constructors/miscellaneous-gis-functions/st_longfromgeohash), and [ST\_PointFromGeoHash](https://app.gitbook.com/s/SsmexDFPv2xG2OTyO5yV/reference/sql-statements/geometry-constructors/miscellaneous-gis-functions/st_pointfromgeohash), improving MySQL 8 compatibility
* [**MariaDB Enterprise Audit**](https://app.gitbook.com/s/SsmexDFPv2xG2OTyO5yV/reference/plugins/mariadb-enterprise-audit) — connection records now log the client port alongside the host, connection events record the negotiated TLS version, on `DISCONNECT` and `CHANGE_USER` as well as `CONNECT`, and the audit log can be written in JSON format ([MENT-2469](https://jira.mariadb.org/browse/MENT-2469), [MENT-2470](https://jira.mariadb.org/browse/MENT-2470), [MENT-2471](https://jira.mariadb.org/browse/MENT-2471))
* [**Galera**](https://app.gitbook.com/o/diTpXxF5WsbHqTReoBsS/s/3VYeeVGUV4AMqrA3zwy7/) **26.4.28** — the replication library incorporated in this release for MariaDB Enterprise Cluster

For the complete list, see [What's New in MariaDB Enterprise Server 12.3](whats-new.md).

This release also includes the changes and improvements made in MariaDB Community Server 12.3, which are not all repeated here. For the upstream list, see [Changes and Improvements in MariaDB 12.3](../../community-server/12.3/mariadb-12.3-changes-and-improvements.md).

## Incompatible Changes

The following keywords are now [reserved words](https://app.gitbook.com/s/SsmexDFPv2xG2OTyO5yV/reference/sql-structure/sql-language-structure/reserved-words) and must be quoted if used as identifiers: `CONVERSION`, `TO_DATE`.

`ST_COLLECT` is not a reserved word, but as an aggregate function it is recognized as the built-in when it appears immediately before an opening parenthesis, so a stored function named `ST_Collect` can no longer be created or called by an unqualified name. The eight other new GIS functions are not affected this way. See [New Built-in Function Names](whats-new.md#new-built-in-function-names) for details.

The deprecated `big_tables`, `large_page_size`, and `storage_engine` system variables have been removed.

See [Incompatible Changes](whats-new.md#incompatible-changes) for details.
