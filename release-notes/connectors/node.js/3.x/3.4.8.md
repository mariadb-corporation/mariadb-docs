## Bug Fixes

* [CONJS-378](https://jira.mariadb.org/browse/CONJS-378) `pool.escape()` returned a backslash-escaped value under `NO_BACKSLASH_ESCAPES` when every connection of the pool was in use, leaving the value injectable (report by buxuwa)
* [CONJS-379](https://jira.mariadb.org/browse/CONJS-379) Fixed SQL injection in `Buffer` parameter escaping under the big5 client charset: the lead bytes 0xFA-0xFE are single bytes for the server (report by fg0x0)
* [CONJS-380](https://jira.mariadb.org/browse/CONJS-380) Fixed SQL injection in string parameter and `escape()` escaping under the big5, gbk, sjis, and cp932 client charsets, the escape being applied before encoding (report by fg0x0)
* [CONJS-381](https://jira.mariadb.org/browse/CONJS-381) A configured collation is always set with `SET NAMES`, so that a charset the server does not support (gb18030 on MariaDB) is refused instead of silently ignored (report by fg0x0)
