# Connector/C++ 1.0.8 Release Notes

{% include "../../../.gitbook/includes/latest-cpp.md" %}

[Download Now](https://mariadb.com/downloads/connectors/connectors-data-access/cpp-connector)

**Release date:** DD Month 2026

This is a [***Stable (GA)***](../../../community-server/about/release-criteria.md) release of MariaDB Connector/C++.

{% hint style="info" %} **For a description of this library see the** [**MariaDB Connector/C++**](https://app.gitbook.com/s/CjGYMsT2MVP4nd3IyW2L/mariadb-connector-cpp) **page.** {% endhint %}

MariaDB Connector/C++ is the interface between C++ applications and MariaDB Server. MariaDB Connector/C++ enables development of C++ applications using a JDBC-based API, which is also used by MariaDB Connector/J.

MariaDB Connector/C++ implements the MySQL protocol using the MariaDB Connector/C API. This release depends on [MariaDB Connector/C 3.3.21](../../c/3.3/3.3.21.md).

## Notable Changes

- [CONCPP-163](https://jira.mariadb.org/browse/CONCPP-163) - Multi-statements are now not allowed by default. Introduced allowMultiQueries option to control if statements batch queries are
allowed
- [CONCPP-161](https://jira.mariadb.org/browse/CONCPP-161) - DatabaseMetaData methods did not consider `NO_BACKSLASH_ESCAPES` sql\_mode real value for escaping parameters
- [CONCPP-162](https://jira.mariadb.org/browse/CONCPP-162) - Wrong quot escaping of parameters in DatabaseMetaData methods
- [CONCPP-164](https://jira.mariadb.org/browse/CONCPP-164) - Savepoint names were not quoted and escaped in the `setSavepoint`, `releaseSavepoint` and `rollback` methods.
Besides incorrect work with names requiring quoting, this created a theoretical opportunity for SQL injection
- [CONCPP-165](https://jira.mariadb.org/browse/CONCPP-165) - The driver has been made more resilient to forged metadata sent by a malicious server.
With server side prepared statements the driver could read past the allocated buffer and return that data to the application, if server sent value length greater than field length.
- [CONCPP-166](https://jira.mariadb.org/browse/CONCPP-166) - Malicious server can write past the buffer and control offset and what to write with specially designed DATE/DATETIME/TIMESTAMP values
- [CONCPP-159](https://jira.mariadb.org/browse/CONCPP-159) - The Infer static analysis has been added to the CI workflow

## Bugs Fixed

- [CONCPP-160](https://jira.mariadb.org/browse/CONCPP-160) - The connector read the binary resultset metadata at the wrong time. That made the calculation of field max length useless, and made the connector allocate larger buffers for the row and resultset cache
- [CONCPP-167](https://jira.mariadb.org/browse/CONCPP-167) - Changing `auto_increment_increment` with `rewriteBatchedStatements` "On", crashed the driver.
