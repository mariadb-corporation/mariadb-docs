# Connector/ODBC 3.2.10 Release Notes

**Release date:** 5 Oct 2026

This is a [Stable (GA)](../../../community-server/about/release-criteria.md) release of MariaDB Connector/ODBC 3.2.

MariaDB Connector/ODBC 3.2.10 is built on top of [MariaDB Connector/C v.3.4.11](../../c/3.4/3.4.11.md).

## Important Changes

* [ODBC-502](https://jira.mariadb.org/browse/ODBC-502) - Connector can send to the server chunks of memory adjacent to the query; that happened with UnixODBC, if a UTF-16 code unit of the query had its low byte equal to the high byte of a surrogate pair leading unit - 0xD8..0xDB
* [ODBC-503](https://jira.mariadb.org/browse/ODBC-503) - Using long server version an evil server could make driver to write error message with the controlled negative offset
* [ODBC-505](https://jira.mariadb.org/browse/ODBC-505) - Positioned operations did not quote column names; if the name contained some special character, that could cause execution error; malicious server could exploit this for SQL injection using specially crafted column names
* [ODBC-504](https://jira.mariadb.org/browse/ODBC-504) - All but SQLTables catalog functions did not sanitize the length of their name parameters; parameters longer than maximum name length could cause buffer overflows; too long names are now rejected with HY090
* [ODBC-506](https://jira.mariadb.org/browse/ODBC-506) - Parameter array operation error could cause buffer overrun in the next such operation; the offset in the parameter arrays was not reset in such case, and the next array operation started from that stale offset
* [ODBC-499](https://jira.mariadb.org/browse/ODBC-499) - Bookmark buffer overflow in case of the array fetch
* [ODBC-500](https://jira.mariadb.org/browse/ODBC-500) - Call to SQLGetDescRec(W) writes past the allocated descriptor area
* [ODBC-497](https://jira.mariadb.org/browse/ODBC-497) - The Infer static analysis has been added to the CI workflow

## Bug Fixes

* [ODBC-501](https://jira.mariadb.org/browse/ODBC-501) - SQLGetDescRec returned wrong record data
* [ODBC-507](https://jira.mariadb.org/browse/ODBC-507) - Parameter arrays with DAE(data-at-execution) parameters did not work
* [ODBC-498](https://jira.mariadb.org/browse/ODBC-498) - Reading the SQL\_ATTR\_METADATA\_ID connection attribute caused stack corruption
