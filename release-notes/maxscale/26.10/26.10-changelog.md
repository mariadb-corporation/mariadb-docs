# MaxScale 26.10 Changelog

{% include "https://app.gitbook.com/s/GxVnu02ec8KJuFSxmB93/~/reusable/DobjxO0sqF3MWCEIIL8Z/" %}

* The MaxScale log now uses ISO 8601 timestamps with UTC offset instead of the
  custom legacy timestamp. To use the old format, add
  `log_timestamp_format=datetime` under the `[maxscale]` section.

* A monitored server may remain in running status despite the monitor
  connection failing, if the failure was due to connection timeout and if
  MaxScale has recently received data from the server in response to a
  client query. These conditions suggest that the server is still running,
  but too busy to process MaxScale monitor connections. `maxctrl list servers`
  shows a "Monitor timed out"-message in the Status Info-field when this
  happens.

* When using the MariaDB Monitor feature
  [cooperative-monitoring](https://app.gitbook.com/o/diTpXxF5WsbHqTReoBsS/s/0pSbu5DcMSW4KwAkUcmX/reference/maxscale-monitors/mariadb-monitor#cooperative-monitoring)
  with automatic cluster manipulation operations such as
  [auto_failover](https://app.gitbook.com/o/diTpXxF5WsbHqTReoBsS/s/0pSbu5DcMSW4KwAkUcmX/reference/maxscale-monitors/mariadb-monitor#auto_failover),
  the monitor will now wait longer to launch an automatic operation if
  it recently gained lock majority. This is to ensure the previous
  primary monitor has time to complete any operation it may have been
  running before the new primary monitor starts another one.

* MariaDB Monitor setting assume_unique_hostnames is deprecated and will be
  removed in a later release. If monitored servers are in a private network,
  use the server setting
  [private\_address](https://app.gitbook.com/o/diTpXxF5WsbHqTReoBsS/s/0pSbu5DcMSW4KwAkUcmX/reference/maxscale-monitors/mariadb-monitor#private_address)
  instead.

* Both MariaDB Monitor and Galera Monitor support external replication
  management by relying on the results of another monitor. This allows the
  monitor to update the external replication connection if the external primary
  goes down or its role changes. See
  [MariaDB Monitor documentation](https://app.gitbook.com/o/diTpXxF5WsbHqTReoBsS/s/0pSbu5DcMSW4KwAkUcmX/reference/maxscale-monitors/mariadb-monitor#external-replication-management)
  and [Galera Monitor documentation](https://app.gitbook.com/o/diTpXxF5WsbHqTReoBsS/s/0pSbu5DcMSW4KwAkUcmX/reference/maxscale-monitors/galera-monitor#external-replication-management)
  for more information.

* If the MariaDB Monitor setting
  [cooperative_monitoring_locks](https://app.gitbook.com/o/diTpXxF5WsbHqTReoBsS/s/0pSbu5DcMSW4KwAkUcmX/reference/maxscale-monitors/mariadb-monitor#cooperative_monitoring_locks)
  is used with the MaxScale setting `passive=true`, the monitor will no longer
  acquire any locks.
  The monitor will assume that another MaxScale will acquire the locks and
  select a primary server.

* MariaDB Monitor now supports [cooperative_monitoring_arbitrator_nodes](https://app.gitbook.com/o/diTpXxF5WsbHqTReoBsS/s/0pSbu5DcMSW4KwAkUcmX/reference/maxscale-monitors/mariadb-monitor#cooperative_monitoring_arbitrator_nodes).
  Arbitrator nodes are only used for cooperative monitoring locks and most
  routers will not route SQL traffic to them.

* MariaDB Monitor config setting `replication_master_ssl` now supports the
  `auto`-value, which causes the monitor to preserve the existing value of
  MASTER_SSL. `auto` is also the new default. See [monitor documentation](https://app.gitbook.com/o/diTpXxF5WsbHqTReoBsS/s/0pSbu5DcMSW4KwAkUcmX/reference/maxscale-monitors/mariadb-monitor#replication_master_ssl)
  for more information. In the REST-API monitor parameters, the
  `replication_master_ssl`-field is now a **string instead of a boolean**.

* MariaDB Monitor can heal a primary server that has truncated its binary logs
  during crash recovery. See [here](https://app.gitbook.com/o/diTpXxF5WsbHqTReoBsS/s/0pSbu5DcMSW4KwAkUcmX/reference/maxscale-monitors/mariadb-monitor#heal_primary_truncated_binlog)
  for more information.

* Listeners now support [SNI](https://en.wikipedia.org/wiki/Server_Name_Indication).
  SNI allows a client to connect to different MaxScale services through one
  listener. This feature is configured with an external JSON file. See
  [listener documentation](https://app.gitbook.com/o/diTpXxF5WsbHqTReoBsS/s/0pSbu5DcMSW4KwAkUcmX/maxscale-management/deployment/installation-and-configuration/maxscale-configuration-guide#sni_mapping_file)
  for more information.

* The `ssl`-setting for listeners and servers is now an enumeration value.
  The allowed values are `disable`, `allow` (default) and `require`.
  The old boolean values are also accepted, and map to either `disable` or
  `require`. See
  [configuration guide](https://app.gitbook.com/o/diTpXxF5WsbHqTReoBsS/s/0pSbu5DcMSW4KwAkUcmX/maxscale-management/deployment/installation-and-configuration/maxscale-configuration-guide#tls-ssl-encryption)
  for more information.

* `ssl=allow` is the new default value, for both listeners and servers. This
  means MaxScale defaults to encrypted backend connections if server supports
  TLS. This can increase CPU usage slightly. To disable encryption for backend
  connections, set `ssl=disable` for each server.

* In the REST-API output for listener and server configurations, the
  `ssl`-field is now a **string instead of a boolean**.

* Switchovers done by the MariaDB Monitor will now wait for open transactions to
  close before proceeding with the switchover. The monitor will wait for
  transactions at most one third of `switchover_timeout`, that is, 30 seconds
  with the default timeout of 90 seconds. This waiting can be disabled with the
  `switchover_wait_for_trx=false` setting in the monitor.

* Due to changes in monitor script handling (the `script`-setting), the script
  needs to start with a shebang (e.g. `#!/usr/bin/env bash`). The PATH
  environment variable is no longer searched.

* The PAM authenticator module now defaults to SUID-mode. See
  [authenticator documentation](https://app.gitbook.com/o/diTpXxF5WsbHqTReoBsS/s/0pSbu5DcMSW4KwAkUcmX/reference/maxscale-authenticators/maxscale-pam-authenticator#pam_mode)
  for more information.

* The QLA Filter supports sending log events to Kafka. See
  [QLAFilter documentation](https://app.gitbook.com/o/diTpXxF5WsbHqTReoBsS/s/0pSbu5DcMSW4KwAkUcmX/reference/maxscale-filters/maxscale-query-log-all-filter)
  for more information.

* New GridGainRouter runs SQL statements on a GridGain cluster over ODBC, and
  can be used as a target of SmartRouter.

* SmartRouter supports `causal_reads`, also when it routes reads to Exasol.

* SmartRouter supports routing hints, which route a read to a chosen cluster.

* Exasol CDC can be started and stopped at runtime, can copy an existing
  MariaDB database and its users into Exasol, can replicate users, roles and
  grants, and can keep data in Exasol when it is deleted in MariaDB.

* The NoSQL protocol supports version 9 of the MongoDB wire protocol, which
  recent clients such as mongosh require.

* Writes to a server can be throttled with `maxctrl set server <name> throttle`.
  Readwritesplit then delays commits until replication catches up, and enables
  `sync_transaction` while the throttling lasts.

* Readwritesplit releases connections to servers that are being drained or are
  in maintenance more actively, and `--force` allows draining and maintenance
  of servers labeled `Write`.

* MaxScale exports its log messages via OpenTelemetry, in addition to metrics.

* Service metrics are exported via OpenTelemetry, and errors are counted for
  every target that returns one.

* Query statistics include latency percentiles per server, and can be sorted
  by hits, last use or duration.

* New log events for the start and end of sessions, with their own levels and
  facilities.

* MaxScale sets the TLS SNI for encrypted connections to MariaDB.

* The REST API can download and install the MariaDB ODBC driver.

* Debug symbols are shipped in a separate package.

* MaxGUI has a diagnostic report for MariaDB support, can stop and start
  listeners, and shows mandatory parameters first.

* Memcached is no longer supported as storage for the MaxScale Cache.

* The avrorouter module has been removed. Use kafkacdc instead.

For more details, please refer to:

* [MariaDB MaxScale 26.10.0 Release Notes](26.10.0.md)

The changelog for the previous MaxScale version can be found [here](../25.10/25.10-changelog.md).
