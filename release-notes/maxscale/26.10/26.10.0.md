# MariaDB MaxScale 26.10.0 Release Notes

Release 26.10.0 is a GA release. It was released on X-Y-Z.

This document describes the changes in release 26.10, when compared to
release 25.10.

For any problems you encounter, please consider submitting a bug
report on [our Jira](https://jira.mariadb.org/projects/MXS).

## Changed Features

### [MXS-6550](https://jira.mariadb.org/browse/MXS-6550) ISO 8601 timestamps in MaxScale log messages

Log messages now use a ISO 8601 timestamp which is a standardized, easy to parse
time format that includes the UTC timezone offset for easier cross-region log
analysis. To use the old legacy timestamp format, add
`log_timestamp_format=datetime` under the `[maxscale]` section. By default, a
warning is logged on startup for existing installations. To silence it, add
`log_timestamp_format=iso_8601` under the `[maxscale]` section.

See [`log_timestamp_format`]({maxscale}/maxscale-management/deployment/installation-and-configuration/maxscale-configuration-guide.md#log_timestamp_format) for more information.

### [MXS-6239](https://jira.mariadb.org/browse/MXS-6239) A passive Maxscale with cooperative monitoring should not acquire exclusive server locks

If the MariaDB Monitor setting
[cooperative_monitoring_locks](https://app.gitbook.com/s/0pSbu5DcMSW4KwAkUcmX/reference/maxscale-monitors/mariadb-monitor.md#cooperative-monitoring-locks)
is used with `passive=true`, the monitor will no longer acquire any locks.
The monitor will assume that another MaxScale will acquire the locks and
select a primary server.

## New Features

### [MXS-7647](https://jira.mariadb.org/browse/MXS-7647) Support wire protocol 9 in NoSQL
### [MXS-7561](https://jira.mariadb.org/browse/MXS-7561) Automatically enable sync\_transaction if throttling starts

Readwritesplit automatically enables `sync_transaction` if the current primary
server is being throttled. Once throttling stops, `sync_transaction` is
disabled. See
[sync_transaction_throttle_rate]({maxscale}/reference/maxscale-routers/maxscale-readwritesplit.md#sync_transaction_throttle_rate)
for more information.

### [MXS-6921](https://jira.mariadb.org/browse/MXS-6921) Add cooperative_monitoring_arbitrator_nodes to MariaDB Monitor

MariaDB Monitor now
supports [cooperative_monitoring_arbitrator_nodes]({maxscale}/reference/maxscale-monitors/mariadb-monitor.md#cooperative-monitoring-arbitrator-nodes).
Arbitrator nodes are only used for cooperative monitoring locks and most routers
will not route SQL traffic to them.

### [MXS-6781](https://jira.mariadb.org/browse/MXS-6781) Add maxctrl command/API to start/stop CDC

### [MXS-6772](https://jira.mariadb.org/browse/MXS-6772) CDC Operation filter prototype

### [MXS-6765](https://jira.mariadb.org/browse/MXS-6765) Add ability to fix a truncated primary to MariaDB Monitor

MariaDB Monitor can heal a primary server that has truncated its binary logs
during crash recovery. See
[here]({maxscale}/reference/maxscale-monitors/mariadb-monitor.md#heal_primary_truncated_binlog)
for more information.

### [MXS-6764](https://jira.mariadb.org/browse/MXS-6764) Make eviction schedule configurable

The smartrouter performance info eviction schedule is now configurable with a
custom schedule with the
[eviction_schedule]({maxscale}/reference/maxscale-routers/maxscale-smartrouter.md#eviction_schedule)
setting.

### [MXS-6612](https://jira.mariadb.org/browse/MXS-6612) exasol cdc sync users

### [MXS-6572](https://jira.mariadb.org/browse/MXS-6572) Write throttling for servers via "set server throttle"

Writes to servers in MaxScale can now be throttled with the `maxctrl set server
<name> throttle` command. If a readwritesplit service uses a server that's being
throttled, it will add a linearly increasing delay to each COMMIT until
replication lag catches up after which transactions proceed as fast as the
replicas can process.

### [MXS-6514](https://jira.mariadb.org/browse/MXS-6514) Actively drain readwritesplit connections

Readwritesplit now more aggressively releases connections to servers that are
being drained. The readwritesplit feature where it drops connections to severely
lagging servers also now deals with idle connections to those servers. Idle
connections to servers being drained or to servers in maintenance mode now drop
connections even without the `--force` option.

### [MXS-6513](https://jira.mariadb.org/browse/MXS-6513) Allow maintenance and drain on all servers with --force

Servers can now be set to maintenance and drain modes even if they're labeled as
`Write` by the monitor if the `--force` flag is used.

### [MXS-6383](https://jira.mariadb.org/browse/MXS-6383) Support "allow" SSL-mode in server configuration

If a server is configured with `ssl=allow`, MaxScale uses TLS if server
supports it, but falls back to unencrypted connections if not.
See [configuration quide](https://app.gitbook.com/s/0pSbu5DcMSW4KwAkUcmX/maxscale-management/deployment/maxscale-configuration-guide.md#tlsssl-encryption)
for more information.

`ssl=allow` is the new default value, which means MaxScale defaults to
encrypted backend connections if available. This can increase CPU usage
slightly. To disable encryption for backend connections, set `ssl=disable`
for each server.

### [MXS-6294](https://jira.mariadb.org/browse/MXS-6294) Export MaxScale logs via OpenTelemetry

MaxScale now also exports all log messages via OpenTelemetry if it has been
configured to export telemetry. The new
[`telemetry_signals`]({maxscale}/maxscale-management/deployment/installation-and-configuration/maxscale-configuration-guide.md#telemetry_signals)
configuration setting controls which signals are sent. By default, both metrics
and logs are sent. The
[`telemetry_url`]({maxscale}/maxscale-management/deployment/installation-and-configuration/maxscale-configuration-guide.md#telemetry_url)
is now interpreted as the base URL where the telemetry is sent. The metrics and
logs endpoints can also be configured with the
[`telemetry_metrics_url`]({maxscale}/maxscale-management/deployment/installation-and-configuration/maxscale-configuration-guide.md#telemetry_metrics_url)
and
[`telemetry_logs_url`]({maxscale}/maxscale-management/deployment/installation-and-configuration/maxscale-configuration-guide.md#telemetry_logs_url)
in case they're not being sent to the same location.

### [MXS-6264](https://jira.mariadb.org/browse/MXS-6264) Exasol cdc initial data migration

### [MXS-6262](https://jira.mariadb.org/browse/MXS-6262) SmartRouter causal read support

### [MXS-6237](https://jira.mariadb.org/browse/MXS-6237) Query statistics display sort order

The `/v1/maxscale/query_classifier/cache` REST-API endpoint now supports a
`sort` option that takes either `hits` which is the default and sorts by the
most frequently used query, `last_used` which sorts by the most recently used
query or by `duration` which sorts queries by the sum of their execution time.

### [MXS-6233](https://jira.mariadb.org/browse/MXS-6233) External replication management in MariaDB Monitor

MariaDB Monitor supports external replication management by relying on the
results of another monitor. This allows the monitor to update the external
replication connection if the external primary goes down or its role changes.
See
[MariaDB Monitor documentation](https://app.gitbook.com/s/0pSbu5DcMSW4KwAkUcmX/reference/maxscale-monitors/mariadb-monitor.md#external-replication-management)
for more information.

### [MXS-6226](https://jira.mariadb.org/browse/MXS-6226) GridGain Router

### [MXS-6102](https://jira.mariadb.org/browse/MXS-6102) If a server keeps sending routing replies, label it as Running regardless of monitoring result

A monitored server may remain in running status if the connection failure was
due to connection timeout and if MaxScale has recently received data from the
server in response to a client query. These conditions suggest that the server
is still running, but too busy to process MaxScale monitor connections.

### [MXS-6090](https://jira.mariadb.org/browse/MXS-6090) Feature request MaxScale 25.10.1 RPMs stripped of symbol tables etc

MaxScale 26.10 now ships debug symbols in a separate package.

### [MXS-6010](https://jira.mariadb.org/browse/MXS-6010) Route queries based on TLS SNI

### [MXS-6000](https://jira.mariadb.org/browse/MXS-6000) Autodownload MariaDB ODBC driver for workspace -> data migration

The new `/v1/sql/odbc/drivers/install` endpoint downloads the MariaDB ODBC
driver version 3.2.9 or newer. If no specific version is requested, the latest
version is downloaded. The downloaded drivers are listed in the
`/v1/sql/odbc/drivers` endpoint so that they are exposed in the API and make it
possible to use them without access to the filesystem.

### [MXS-5999](https://jira.mariadb.org/browse/MXS-5999) Kafka support for QLAFilter

### [MXS-5990](https://jira.mariadb.org/browse/MXS-5990) Set TLS Server Name Indication for backend connections

MaxScale now sets the TLS SNI for encrypted connections to MariaDB.

### [MXS-5976](https://jira.mariadb.org/browse/MXS-5976) Add SNI support

Listeners now support [SNI](https://en.wikipedia.org/wiki/Server_Name_Indication).
SNI allows a client to connect to different MaxScale services through one
listener. This feature is configured with an external JSON file. See
[listener documentation](https://app.gitbook.com/s/0pSbu5DcMSW4KwAkUcmX/maxscale-management/deployment/maxscale-configuration-guide.md#sni_mapping_file)
for more information.

### [MXS-5975](https://jira.mariadb.org/browse/MXS-5975) Separate and simplify log connection/disconnection info

New log event types have been added for new sessions and closed sessions which
can be controlled with the following settings:
* [`event_session_start_level`]({maxscale}/maxscale-management/deployment/installation-and-configuration/maxscale-configuration-guide.md#event_session_start_level)
* [`event_session_start_facility`]({maxscale}/maxscale-management/deployment/installation-and-configuration/maxscale-configuration-guide.md#event_session_start_facility)
* [`event_session_stop_level`]({maxscale}/maxscale-management/deployment/installation-and-configuration/maxscale-configuration-guide.md#event_session_stop_level)
* [`event_session_stop_facility`]({maxscale}/maxscale-management/deployment/installation-and-configuration/maxscale-configuration-guide.md#event_session_stop_facility)

### [MXS-5768](https://jira.mariadb.org/browse/MXS-5768) Improve MaxScale Query Statistics

MaxScale now tracks query latency percentiles per server. These are available in
the REST-API at `/v1/maxscale/query_classifier/cache/` and with
`maxctrl show query_statistics`.

### [MXS-5609](https://jira.mariadb.org/browse/MXS-5609) MaxGUI should sort parameters so that mandatory parameters are shown first

### [MXS-5594](https://jira.mariadb.org/browse/MXS-5976) Allow encrypted and unencrypted connections on the same listener

A listeners now accepts encrypted and unencrypted connections if configured with `ssl=allow`.
See [configuration quide](https://app.gitbook.com/s/0pSbu5DcMSW4KwAkUcmX/maxscale-management/deployment/maxscale-configuration-guide.md#tlsssl-encryption)
for more information.

### [MXS-5555](https://jira.mariadb.org/browse/MXS-5555) Improve smoothness of switchovers when used with readwritesplit

Mariadbmon now waits for open transactions from readwritesplit to close before
proceeding with a switchover. This makes switchovers a lot less disruptive. With
`delayed_retry=true` in readwritesplit, switchovers should be completely
invisible under normal conditions. See
[switchover_wait_for_trx]({maxscale}/maxscale/reference/maxscale-monitors/mariadb-monitor.md#switchover_wait_for_trx)
for more information.

### [MXS-5375](https://jira.mariadb.org/browse/MXS-5375) Add stop/start listener to the GUI

### [MXS-5335](https://jira.mariadb.org/browse/MXS-5335) Cluster status report feature

### [MXS-4819](https://jira.mariadb.org/browse/MXS-4819) External replication management in Galera Monitor

Galera Monitor supports external replication management by relying on the
results of another monitor. This allows the monitor to update the external
replication connection if the external primary goes down or its role changes.
See
[Galera Monitor documentation](https://app.gitbook.com/s/0pSbu5DcMSW4KwAkUcmX/reference/maxscale-monitors/galera-monitor.md#external-replication-management)
for more information.

### [MXS-3577](https://jira.mariadb.org/browse/MXS-3577) MariaDB Monitor should preserve and transfer the MASTER_SSL option of CHANGE MASTER TO

MariaDB Monitor config setting `replication_master_ssl` now supports the
`auto`-value, which causes the monitor to preserve the existing value of
MASTER_SSL. See [monitor documentation](https://app.gitbook.com/s/0pSbu5DcMSW4KwAkUcmX/reference/maxscale-monitors/mariadb-monitor.md#replication_master_ssl)
for more information.
