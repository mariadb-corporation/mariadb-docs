# MariaDB Enterprise Kubernetes Operator 26.10.3 Release Notes

MariaDB Enterprise Kubernetes Operator 26.10.3 is a maintenance release of the 26.10 (LTS) line, released on 2026-11-30.

**Release Date**: 30 November 2026

Release 26.10.3 is a maintenance release.

This document describes the changes in release 26.10.3, when compared to release 26.10.2.

If you are updating from a previous version, **please follow the** [**UPDATE GUIDE**](https://mariadb.com/docs/tools/enterprise/mariadb-enterprise-operator/updates/update-26.10.3) to ensure a safe transition.

## Bug Fixes

* [K8SDKR-391](https://jira.mariadb.org/browse/K8SDKR-391) The operator no longer reconfigures a primary that lost all its replicas, for example during a network partition, once replication has been configured. With semi-synchronous replication, the replication user statements (`ALTER USER` and `GRANT`) that the operator ran on it are written to the binary log, so they waited for an acknowledgement that never arrived. This blocked the reconciliation of the `MariaDB`, left an errant GTID on the primary and made the MaxScale demotion (`SET GLOBAL read_only=1`) fail with `Error 1969`. The replication user statements are also bounded now by a 30 second timeout.
* [K8SDKR-376](https://jira.mariadb.org/browse/K8SDKR-376) Changes to `spec.podDisruptionBudget` of a `MariaDB` or a `MaxScale` are now applied to the existing `PodDisruptionBudget`, for example changing `minAvailable` from `1` to `2`. The operator now owns the `PodDisruptionBudget` it creates, and reconciles it:
  * Removing `spec.podDisruptionBudget` restores the default (`minAvailable: 50%`) for HA `MariaDB` resources and `MaxScale` resources with more than one replica. For the rest, the operator deletes the `PodDisruptionBudget` it created.
  * Manual changes to the operator-managed `PodDisruptionBudget` are reverted. Refer to the [Pod Disruption Budgets documentation](https://mariadb.com/docs/tools/enterprise/mariadb-enterprise-operator/topologies/high-availability#pod-disruption-budgets).
  * The operator needs the `delete` verb on `poddisruptionbudgets`. The Helm chart grants it.
