# MariaDB Enterprise Kubernetes Operator 26.06.8 Release Notes

MariaDB Enterprise Kubernetes Operator 26.06.8 is a maintenance release of the 26.06 line, released on 2026-11-13.

**Release Date**: 13 November 2026

Release 26.06.8 is a maintenance release.

This document describes the changes in release 26.06.8, when compared to release 26.06.7.

If you are updating from a previous version, **please follow the** [**UPDATE GUIDE**](https://mariadb.com/docs/tools/enterprise/mariadb-enterprise-operator/updates/update-26.06.8) to ensure a safe transition.

For any problems you encounter, please consider submitting a bug report on [our Jira](https://jira.mariadb.org/projects/K8SDKR).

## Bug Fixes

* [K8SDKR-364](https://jira.mariadb.org/browse/K8SDKR-364) Point-in-time recovery with `strictMode` no longer fails with `timeline did not reach target time` when the target time falls inside the last archived binary log.
* [K8SDKR-361](https://jira.mariadb.org/browse/K8SDKR-361) A `PhysicalBackup` of a replica no longer leaves the replica SQL thread stopped when its `Job` retries after `mariadb-backup --safe-slave-backup` stopped the thread. This left the `MariaDB` not ready and, with `mariaDbRef.waitForIt: true`, paused every `PhysicalBackup`. Once a `PhysicalBackup` `Job` finishes and no other `PhysicalBackup` `Job` of the same `MariaDB` is running, the operator now starts the SQL thread of every replica where it is stopped without an error, and emits a `ReplicaSQLThreadStarted` event. Refer to the [physical backup documentation](https://mariadb.com/docs/tools/enterprise/mariadb-enterprise-operator/backup-and-restore/physical_backup#target-policy).
* [K8SDKR-352](https://jira.mariadb.org/browse/K8SDKR-352) The operator image now ships the public CA bundle of its Red Hat UBI base image, so every Go TLS client in the image trusts publicly trusted CAs: the operator and the backup, restore and PITR Jobs. Previously the image had no CA bundle, and the Workload Identity token exchange with Microsoft Entra failed with `x509: certificate signed by unknown authority` when using a managed identity to access Azure Blob Storage. This release also changes the following:
  * `tls.caSecretKeyRef` is now optional for S3 and Azure Blob storage. Setting `tls.enabled: true` without it made the operator panic or fail with `unable to add CA cert to pool`, and it now trusts the publicly trusted CAs.
  * The CA bundle in the `tls.caSecretKeyRef` of Azure Blob storage is now added to the publicly trusted CAs instead of replacing them, which is how S3 already behaved.
