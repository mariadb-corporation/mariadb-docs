# MariaDB Enterprise Kubernetes Operator 26.06.10 Release Notes

MariaDB Enterprise Kubernetes Operator 26.06.10 is a maintenance release of the 26.06 line, released on 2026-11-30.

**Release Date**: 30 November 2026

Release 26.06.10 is a maintenance release.

This document describes the changes in release 26.06.10, when compared to release 26.06.9.

{% hint style="warning" %}
**The 26.06 line is deprecated, and 26.06.10 is its last release.** We recommend updating to the [26.10 (LTS)](../26.10/) line. Refer to the [26.10 update guide](https://mariadb.com/docs/tools/enterprise/mariadb-enterprise-operator/updates/update-26.10).
{% endhint %}

If you are updating from a previous version, **please follow the** [**UPDATE GUIDE**](https://mariadb.com/docs/tools/enterprise/mariadb-enterprise-operator/updates/update-26.06.10) to ensure a safe transition.

## Bug Fixes

* [K8SDKR-391](https://jira.mariadb.org/browse/K8SDKR-391) The operator no longer reconfigures a primary that lost all its replicas, for example during a network partition, once replication has been configured. With semi-synchronous replication, the replication user statements (`ALTER USER` and `GRANT`) that the operator ran on it are written to the binary log, so they waited for an acknowledgement that never arrived. This blocked the reconciliation of the `MariaDB`, left an errant GTID on the primary and made the MaxScale demotion (`SET GLOBAL read_only=1`) fail with `Error 1969`. The replication user statements are also bounded now by a 30 second timeout.
