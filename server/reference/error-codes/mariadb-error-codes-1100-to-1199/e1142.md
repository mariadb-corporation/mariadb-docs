# Error 1142: Command denied to user for table

| Error Code | SQLSTATE | Error                          | Description                                             |
| ---------- | -------- | ------------------------------ | ------------------------------------------------------- |
| 1142       | 42000    | ER\_TABLEACCESS\_DENIED\_ERROR | %s command denied to user '%s'@'%s' for table `%s`.`%s` |

## Possible Causes and Solutions

The account doesn't have the privilege that the statement needs on the table. The message names the missing privilege, such as `SELECT`, `INSERT`, `CREATE VIEW` or `SHOW VIEW`, and the table. For example:

```
SELECT * FROM shop.c1;
ERROR 1142 (42000): SELECT command denied to user 'p'@'localhost' for table `shop`.`c1`

INSERT INTO shop.acct VALUES ();
ERROR 1142 (42000): INSERT command denied to user 'p'@'localhost' for table `shop`.`acct`
```

The server returns the same error for a table that doesn't exist, so that the error doesn't show which tables exist.

To solve the error:

* Check the account's privileges with [SHOW GRANTS](../../sql-statements/administrative-sql-statements/show/show-grants.md).
* Have an administrator [GRANT](../../sql-statements/account-management-sql-statements/grant.md) the privilege, on the table or on the whole database. For example, `GRANT SELECT ON shop.c1 TO 'p'@'localhost'` or `GRANT SELECT ON shop.* TO 'p'@'localhost'`.
* If the privilege was granted to a [role](../../../security/user-account-management/roles/roles_overview.md), enable the role with [SET ROLE](../../sql-statements/account-management-sql-statements/set-role.md) first, or have an administrator make it your default role with [SET DEFAULT ROLE](../../sql-statements/account-management-sql-statements/set-default-role.md).
* If the account has privileges on some columns only, select those columns by name. `SELECT *` gives this error, and a column without the privilege gives [error 1143](e1143.md) instead.

Missing privileges on a whole database give [error 1044](../mariadb-error-codes-1000-to-1099/e1044.md), on a stored routine [error 1370](../mariadb-error-codes-1300-to-1399/e1370.md), and missing global privileges give [error 1227](../mariadb-error-codes-1200-to-1299/e1227.md).
