# Error 1044: Access denied for user

| Error Code | SQLSTATE | Error                       | Description                                       |
| ---------- | -------- | --------------------------- | ------------------------------------------------- |
| 1044       | 42000    | ER\_DBACCESS\_DENIED\_ERROR | Access denied for user '%s'@'%s' to database '%s' |

## Possible Causes and Solutions

The account has no privileges on the database it tries to use. This happens, for example, with [USE](../../sql-statements/administrative-sql-statements/use-database.md), with [CREATE DATABASE](../../sql-statements/data-definition/create/create-database.md), or when you connect with a default database, such as `mariadb -D shop`:

```
USE priv;
ERROR 1044 (42000): Access denied for user 'p'@'localhost' to database 'priv'

CREATE DATABASE newdb;
ERROR 1044 (42000): Access denied for user 'p'@'localhost' to database 'newdb'
```

The server returns the same error for a database that doesn't exist, so that the error doesn't show which databases exist.

To solve the error:

* Check the account's privileges with [SHOW GRANTS](../../sql-statements/administrative-sql-statements/show/show-grants.md). [CURRENT\_USER()](../../sql-functions/secondary-functions/information-functions/current_user.md) shows which account the server matched for the session. It can differ from the user name you logged in with, for example when an anonymous account matches first.
* Have an administrator [GRANT](../../sql-statements/account-management-sql-statements/grant.md) the privileges on the database, for example `GRANT SELECT, INSERT ON shop.* TO 'p'@'localhost'`.
* If the privileges were granted to a [role](../../../security/user-account-management/roles/roles_overview.md), they apply only after you enable the role with [SET ROLE](../../sql-statements/account-management-sql-statements/set-role.md), or after an administrator makes it your default role with [SET DEFAULT ROLE](../../sql-statements/account-management-sql-statements/set-default-role.md).

A wrong password or an unknown account gives [error 1045](e1045.md) instead, when you connect. Missing privileges on a table give [error 1142](../mariadb-error-codes-1100-to-1199/e1142.md), and missing global privileges give [error 1227](../mariadb-error-codes-1200-to-1299/e1227.md).
