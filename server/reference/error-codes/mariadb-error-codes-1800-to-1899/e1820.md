# Error 1820: You must SET PASSWORD before executing this statement

| Error Code | SQLSTATE | Error                      | Description                                           |
| ---------- | -------- | -------------------------- | ----------------------------------------------------- |
| 1820       | HY000    | ER\_MUST\_CHANGE\_PASSWORD | You must SET PASSWORD before executing this statement |

## Possible Causes and Solutions

The password of the account has [expired](../../../security/user-account-management/user-password-expiry.md), and the session runs in sandbox mode. A password expires when an administrator runs `ALTER USER … PASSWORD EXPIRE`, or when it is older than its lifetime, set with `PASSWORD EXPIRE INTERVAL` or [default\_password\_lifetime](../../../ha-and-performance/optimization-and-tuning/system-variables/server-system-variables.md#default_password_lifetime).

In sandbox mode, the server accepts only `SET` statements, including [SET PASSWORD](../../sql-statements/account-management-sql-statements/set-password.md), and prepared-statement commands. Every other statement, `ALTER USER` included, fails with this error:

```
SELECT 1;
ERROR 1820 (HY000): You must SET PASSWORD before executing this statement
```

To solve the error, set a new password in the same session. The session then works normally:

```sql
SET PASSWORD = PASSWORD('new_password');
```

An administrator can also set a new password for the account with `ALTER USER`, or remove the expiry with `ALTER USER … PASSWORD EXPIRE NEVER`.

Whether a client with an expired password gets a sandbox session at all depends on [disconnect\_on\_expired\_password](../../../ha-and-performance/optimization-and-tuning/system-variables/server-system-variables.md#disconnect_on_expired_password). When it's on, a client that doesn't support sandbox mode is refused at login with [error 1862](e1862.md).
